# Standup File Format Spec

This document specifies the on-disk format of the daily standup Markdown files that `autostand` produces, consumes, and merges. It covers the file path, full structure, block grammar, AUTO body grammar, invariants, parsing rules, and migration from the prior App Script.

---

## File path

```
<dailies_dir>/YYYY-MM-DD.md
```

- Default `<dailies_dir>` = `<repo>/dailies/` (configurable via `dailies_dir`).
- The filename date is the **filing date** `F` — the next business day after the work day. Work done on day `D` is reported in `F = next_business_day(D)`.
- `next_business_day(D)` skips Saturday and Sunday. Holidays are **not** skipped (autostand does not ship a holiday calendar; extendable via config).
- Examples:
  - Work on `2026-08-01` (Sat) → `F = 2026-08-03` (Mon).
  - Work on `2026-08-04` (Tue) → `F = 2026-08-05` (Wed).
  - Work on `2026-08-07` (Fri) → `F = 2026-08-10` (Mon).

The same `F` is used for: the filename, the title date, the audit sidecar name, and the git commit subject.

## Full structure

```markdown
# Daily Standup — August 03, 2026
_Work completed August 01–02, 2026._

<!-- AUTO:MacStudio-de-Miguel:START -->
**autostand — [FIF-133](https://fiftyflowers.atlassian.net/browse/FIF-133) — Tauri port scaffolding**
- Implemented `autostand-core` domain model structs
- Wrote 6 architecture docs under `docs/architecture/`

**General — Documentation**
- Drafted design system token specification

**PR Review**
- autostand #12 — "Add IPC contracts" (by @contributor) — Approved
<!-- AUTO:MacStudio-de-Miguel:END -->

<!-- AUTO:MacBook-Pro-de-Miguel:START -->
**my-repo — [FIF-140](https://fiftyflowers.atlassian.net/browse/FIF-140) — Bug fix**
- Fixed race condition in queue processor
<!-- AUTO:MacBook-Pro-de-Miguel:END -->

<!-- MANUAL:START -->
<!-- Items added via "add to my standup" live here; auto-compile never touches them. -->
- Attended architecture review meeting at 14:00
<!-- MANUAL:END -->
```

### Anatomy

| Region | Lines | Owner | Editable by user? |
| --- | --- | --- | --- |
| Title | `# Daily Standup — <Month DD, YYYY>` | `autostand-core::format` | Yes (but overwritten on recompile) |
| Subtitle | `_Work completed <range_start>–<range_end>, <year>._` | `autostand-core::format` | Yes (but overwritten on recompile) |
| `AUTO:<host>:START … END` | one block per host | the host that owns the block | No (regenerated by that host's pipeline) |
| `MANUAL:START … END` | exactly one, global | user only — `add_manual_item` appends | Yes — `autostand` never overwrites the inner content |

## Block grammar

### EBNF

```ebnf
file        = title, newline, subtitle, newline, newline, { auto_block }, manual_block ;

title       = "# Daily Standup — ", month_day_year ;
subtitle    = "_Work completed ", range_start, "–", range_end, ", ", year, "._" ;

auto_block  = auto_start, newline, auto_body, newline, auto_end, newline ;
auto_start  = "<!-- AUTO:", host_slug, ":START -->" ;
auto_end    = "<!-- AUTO:", host_slug, ":END -->" ;
auto_body   = { section } ;

manual_block = manual_start, newline, manual_body, newline, manual_end ;
manual_start = "<!-- MANUAL:START -->" ;
manual_end   = "<!-- MANUAL:END -->" ;

section     = section_header, newline, { bullet } ;
section_header = "**", section_title, "**" ;
bullet      = "- ", text, newline ;
```

### Regex (for the parser)

```regex
AUTO_BLOCK   = <!--\sAUTO:(?P<host>[A-Za-z0-9_-]+):START\s-->\n(?P<body>.*?)\n<!--\sAUTO:\1:END\s-->
MANUAL_BLOCK = <!--\sMANUAL:START\s-->\n(?P<body>.*?)\n<!--\sMANUAL:END\s-->
```

Flags: `re.DOTALL` is **not** needed because the parser splits on lines first, then matches block-by-block. The `.*?` is non-greedy across newlines when matching the body slice directly.

### Invariants

1. **One AUTO block per host.** A file may contain blocks for many hosts (multi-machine setup), but no two blocks share a host slug.
2. **Exactly one global MANUAL block.** It lives at the end of the file, after all AUTO blocks.
3. **AUTO blocks are ordered by first-write.** `fileops` preserves existing order when recompiling; a new host's block is inserted immediately before `<!-- MANUAL:START -->`.
4. **Block tags are case-sensitive.** `AUTO:` and `MANUAL:` are uppercase; `START`/`END` are uppercase; the host slug is preserved verbatim.
5. **No nested blocks.** A block body never contains `<!-- AUTO:` or `<!-- MANUAL:`.

## AUTO body grammar

### Section header

```regex
^\*\*(?P<title>[^*]+)\*\*$
```

The title is one of:

| Kind | Format | Example |
| --- | --- | --- |
| Repo section | `<repo-name> — [<JIRA-KEY>](<jira-url>) — <summary>` | `autostand — [FIF-133](https://fiftyflowers.atlassian.net/browse/FIF-133) — Tauri port scaffolding` |
| General section | `General — <topic>` | `General — Documentation` |
| Spike section | `<Spike name>` | `Auth Refactor Spike` |
| Docs section | `Documentation & Tooling` | `Documentation & Tooling` |
| PR Review section | `PR Review` | `PR Review` |

Only the Jira key is a Markdown link; `repo-name` is plain text.

### Bullets

```regex
^-\s+.+$
```

- Past-tense, concrete description: `- Fixed race condition in queue processor`.
- One bullet per discrete unit of work.
- Bullets are never nested (no sub-bullets under a section).

### PR Review section

The PR Review section is always the **trailing** section of an AUTO block (if present). One bullet per PR reviewed:

```markdown
**PR Review**
- autostand #12 — "Add IPC contracts" (by @contributor) — Approved
- my-repo #45 — "Refactor queue" (by @other) — Changes requested
```

Format: `<repo> #<num> — "<title>" (by @<author>) — <state>`

## Invariants

### `.gitattributes` (in the dailies repo)

```gitattributes
20YY-MM-DD.md merge=union
```

The `union` merge driver concatenates both sides of a conflict instead of emitting `<<<<<<<` markers. This is what lets two machines append AUTO blocks for different hosts to the same date file without manual resolution.

### File modes

| State | Mode | Why |
| --- | --- | --- |
| Written by autostand on current machine | `0600` | `tempfile::NamedTempFile` default; never chmod'd back. Owner-only read/write. |
| Stored in git | `0644` | Standard checkout mode. World-readable content (standup summaries are not secrets). |

### Atomic write

```rust
fn write_file_atomic(path: &Path, body: &str) -> Result<()> {
    let dir = path.parent().unwrap();
    let mut tmp = tempfile::NamedTempFile::new_in(dir)?;
    tmp.write_all(body.as_bytes())?;
    tmp.as_file().sync_all()?;           // fsync
    tmp.persist(path)?;                  // atomic rename
    Ok(())
}
```

### Host slug

- Persisted to `state/host-id` on first run; never re-detected.
- Never DHCP-derived (no IP addresses).
- Rejected if numeric (`^\d+$`) or IP-like (`^\d+\.\d+\.\d+\.\d+$`).
- See `docs/tauri/03-platform-targets.md` for per-platform detection.

### Title format

```
# Daily Standup — <Month DD, YYYY>
```

- Full month name (`August`, not `Aug`).
- Day-of-month without leading zero (`3`, not `03`).
- Year as 4 digits.

### Subtitle format

```
_Work completed <range_start>–<range_end>, <year>._
```

- `range_start` and `range_end` use the same `Month DD` format (no leading zero).
- Range separator is the **en-dash** `–` (U+2013), **not** a hyphen `-`.
- Year as 4 digits.
- Wrapped in italics (`_…_`).
- If `range_start == range_end` (single-day window), the subtitle is `_Work completed <Month DD>, <year>._` (no dash).

## Parsing rules

Implemented in `autostand-core::format::parse_file`. The parser is **tolerant** — it must handle partially-written files, union-merge artifacts, and concurrent writers.

1. **Read file** (or return an empty skeleton if the file does not exist).
2. **Extract title and subtitle** from the first two non-empty lines. If missing, synthesize them from the filename date.
3. **Find all AUTO blocks** with the regex above. Collect into `Vec<AutoBlock { host, body }>`.
4. **Collapse duplicate AUTO blocks for the same host** (can occur after `merge=union` concatenates two versions). Merge bodies by concatenating unique sections (dedup by section header + bullet text).
5. **Extract the MANUAL region verbatim** (inner lines between `MANUAL:START` and `MANUAL:END`). If missing, synthesize an empty MANUAL block on write.
6. **Build the skeleton** if the file is empty or missing:
   ```
   # Daily Standup — <Month DD, YYYY>
   _Work completed <range_start>–<range_end>, <year>._

   <!-- MANUAL:START -->
   <!-- MANUAL:END -->
   ```
7. **Extract a specific host's AUTO block as `PREV`** for the `accumulate` step. `PREV` is the prior content for the current host, used to re-inject uncovered bullets.

### Rust sketch

```rust
// crates/autostand-core/src/format.rs
use regex::Regex;
use once_cell::sync::Lazy;

static AUTO_RE: Lazy<Regex> = Lazy::new(|| Regex::new(
    r"<!--\sAUTO:(?P<host>[A-Za-z0-9_-]+):START\s-->\n(?P<body>.*?)\n<!--\sAUTO:\1:END\s-->"
).unwrap());

static MANUAL_RE: Lazy<Regex> = Lazy::new(|| Regex::new(
    r"<!--\sMANUAL:START\s-->\n(?P<body>.*?)\n<!--\sMANUAL:END\s-->"
).unwrap());

pub struct ParsedFile {
    pub title: String,
    pub subtitle: String,
    pub auto_blocks: Vec<AutoBlock>,
    pub manual_region: String,
}

pub fn parse_file(content: &str) -> ParsedFile {
    let mut lines = content.lines();
    let title    = lines.next().unwrap_or_default().to_string();
    let subtitle = lines.next().unwrap_or_default().to_string();

    let mut auto_blocks: Vec<AutoBlock> = AUTO_RE
        .captures_iter(content)
        .map(|c| AutoBlock {
            host: c.name("host").unwrap().as_str().to_string(),
            body: c.name("body").unwrap().as_str().to_string(),
        })
        .collect();

    auto_blocks = collapse_duplicates(auto_blocks);

    let manual_region = MANUAL_RE
        .captures(content)
        .map(|c| c.name("body").unwrap().as_str().to_string())
        .unwrap_or_default();

    ParsedFile { title, subtitle, auto_blocks, manual_region }
}
```

## Migration note

The prior **App Script** (Google Apps Script) wrote standups to `~/Sync/Github_Dailies/`. `autostand` uses `<repo>/dailies/` by default (configurable via `dailies_dir`), so existing App Script output can be pointed at by setting `dailies_dir = ~/Sync/Github_Dailies` in config during the transition.

### Required: `.gitattributes` in the dailies repo

For the `union` merge driver to work, the dailies repo must contain:

```gitattributes
20YY-MM-DD.md merge=union
```

This tells git to invoke the built-in `union` merge driver for files matching `20YY-MM-DD.md`. The driver concatenates both sides of a conflict instead of emitting conflict markers, which is what lets two machines append AUTO blocks for different hosts to the same date file without manual resolution.

If the dailies repo was previously used by the App Script, add this file once and commit it. No rebase of history is needed.
